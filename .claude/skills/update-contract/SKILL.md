# Update the contract

Run the ingestion pipeline against a new PWA edition and verify what comes out. Paths are
relative to the repository root; `$PWA_DATA_DIR` overrides `data/`.

## Prerequisites

- The new PDF at `data/original/live-contract.pdf`
- `ANTHROPIC_API_KEY` set (in `.env` or the environment) — used for the pages the text
  layer cannot provide
- `pdftotext` and `pdftoppm` (poppler) on PATH
- Dependencies installed: `pip install -e .`

## Steps

### 1. Back up the current text

```bash
D=$(date +%Y%m%d)
mkdir -p "data/backup_$D"
cp -r data/sections data/loa data/mou data/extracted/live-contract-full.md "data/backup_$D"/
```

### 2. Put the new PDF in place

```bash
cp /path/to/new-pwa.pdf data/original/live-contract.pdf
```

### 3. Clear the OCR cache

The cache is keyed by **page number**. A new edition is almost always repaginated, so
stale entries would be silently reused against the wrong pages.

```bash
rm -rf data/extracted/ocr_cache
```

### 4. Extract

```bash
python3 pipeline/extract_contract.py --dry-run   # classification only, no API calls
python3 pipeline/extract_contract.py
```

The dry run reports how many pages need OCR and why — `sparse` (no usable text layer) or
`scrambled` (custom font encoding). Expect on the order of 15%. **If it reports nearly
every page**, the PDF probably has no text layer at all; investigate before spending the
API calls, because the cost scales with that number.

Successful pages are cached, so a rerun after a failure only redoes what failed.

### 5. Split into per-document files

```bash
python3 pipeline/split_contract.py --dry-run     # review the page -> document map
python3 pipeline/split_contract.py
```

Read the dry-run map before writing. Every page from the first section divider onward
should be assigned, and page ranges should be contiguous with no gaps.

### 6. Verify

```bash
grep -rl "OCR FAILED" data/sections data/loa data/mou   # must print nothing
```

`data/INDEX.md` was just regenerated by the split — read it. It gives the document counts,
every title, and the page range each document occupies, which is enough for both checks
below.

1. **Against the contract's own inventory.** Section 29 C. lists every LOA and MOU that
   survives the PWA. The index must match it exactly — the best available check that
   nothing was missed or absorbed into a neighbouring document. Also confirm page ranges
   are contiguous, with no document swallowing its neighbour.
2. **Pay tables.** Image-only pages, so they depend entirely on OCR, and they are the
   highest-stakes data in the contract. Re-rasterize the relevant pages
   (`pdftoppm -png -r 200 -f N -l N data/original/live-contract.pdf /tmp/page`), read the
   image, and compare cell-for-cell against the extracted table.

### 7. Update the documentation

`data/INDEX.md` is regenerated automatically — nothing to do there. Nothing in the
repository lists the contract's contents, by design, so the only thing that may need
touching is `README.md`, if the edition or the extraction statistics quoted in it changed.

## Reference handbooks

Separate pipeline, since these have no usable text layer at all — screenshots of the
bidding and scheduling software carry much of the content.

```bash
# PDFs go in data/original/handbooks/, one per handbook
python3 pipeline/transcribe_handbooks.py submit
python3 pipeline/transcribe_handbooks.py poll
python3 pipeline/transcribe_handbooks.py collect
```

Output lands in `data/handbooks/<name>.md`. Batch jobs typically finish well inside the
24-hour window; `poll` blocks until they end.

## Troubleshooting

### Pages assigned to the wrong document

`split_contract.py` identifies documents from the running page header and forward-fills
pages without one. Two known wrinkles, both already handled — but worth re-checking on a
new edition:

- Some documents carry only a bare number in the header (`MOU #25-01`) and name themselves
  further down the page. Titles therefore come from the table of contents, not the header.
- The table of contents itself names every document, so pages before the Section 1 tab
  divider are excluded from identification or they would match as document starts.

If the TOC moves off pages 3–5, adjust `TOC_PAGES` / `FIRST_DOC_PAGE` in the script.

### Mojibake left in the output

Some pages use a custom font encoding that extracts as mojibake (`/2$` for `LOA`). It is a
uniform shift — every character sits 29 below its true value, with the space written as
`\x03` — so it is recoverable rather than lost. Two paths handle it:

- **Fully scrambled pages** go to OCR. `extract_contract.py` detects them by testing
  whether unshifting the page yields more common English words than the raw text does.
- **Mixed pages**, where only the running header or a caption is encoded, are repaired in
  place by `decode_mojibake()` and keep their exact text layer.

Decoding is token-by-token and deliberately conservative, because ordinary text shares the
same character range — `UNDERSTANDING`, `2026`, the margin line numbers and the rest
facility code `4A/2D` all unshift into plausible-looking nonsense. A token is decoded only
when unshifting it reveals a word the document actually uses. If a new edition leaves
mojibake behind, the likely cause is a short term missing from the learned vocabulary; add
it to `SEED_VOCAB` in `pipeline/extract_contract.py`.

### API errors

`extract_contract.py` retries five times with exponential backoff and marks anything that
still fails with `<!-- OCR FAILED ... -->`, exiting non-zero. Re-run it — cached pages are
skipped, so only the failures are retried.
